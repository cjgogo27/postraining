## 随机切窗口为什么容易高估收益

一份手册先切成100个窗口，再随机拿20个当验证。训练里仍有同一型号、同一句故障解释和相邻页码；验证可能只是在考“还记不记得刚看过的句子”。

## 先建立组，再分，再切

```text
解析文档 → 精确/近似重复关系 → 实体/来源/时间组
                  → train / dev / test → 各自编码和窗口化
```

精确哈希找相同文本；近似去重可用分片集合相似性等办法找改写或复制片段。阈值应通过误删/漏删样本校准，不能把“做了MinHash”当作没有泄漏的证明。重复关系可能跨文档或跨站点，组ID不是文件名的另一个写法。

## 三种留出，问的是三种问题

| 留出对象 | 能较直接检查什么 | 仍不能说明什么 |
| --- | --- | --- |
| 同实体的新文档 | 文档级重复依赖是否降低 | 新实体泛化 |
| 新实体、同模板 | 实体ID变化后的同格式适配 | 新模板、新任务 |
| 新模板/主题/时间 | 更强的分布迁移 | 所有现实场景已覆盖 |

本站NX/GX各有64训练、16验证实体，共160条唯一文档；训练组与验证组不交叉。四类标签及模板仍共用，刻意保留这个限制。实验没有近似去重或污染检测算法的生产运行结果。

## 去污染要写清针对什么

从训练语料排除评测题的原文、答案段落、近似改写或同源生成，各自范围不同。数学公式、代码片段和短通用句可能高频重合；筛选过严会误删正常知识，过松又留下泄漏。保留命中规则、排除数量和抽检样例。

即使没有文本重合，教师可能已经见过题；合成链、人工标注和反复选方案也会带来盲区。因此“去污染通过”是对某一规则和语料版本的陈述，不能成为成绩绝对可信的保证。

## 用Jaccard手算理解近似去重

把两个短文档切成shingle集合，假设`A={a,b,c,d}`、`B={a,b,c,e}`。交集3项，并集5项，Jaccard相似度为3/5=0.6。完全相同文本的哈希很容易查，少改一词却会改变精确哈希；集合相似性让这种近似关系可被候选检索发现。

MinHash用较短签名估计这类集合重合，LSH把可能相似的文档放入候选桶，再按约定复核。[BigCode官方去重讲解](https://huggingface.co/blog/dedup#minhash-walkthrough)展示了shingle、签名、LSH和聚类的连接。中文、代码和表格的切片单位不同，不能直接继承英文网页阈值。

## 去重关系会传递，但相似度不必传递

```text
A ──相似── B ──相似── C
把连通组{A,B,C}放入同一数据划分
但A和C不一定达到同一个成对相似阈值
```

若只删除成对重复，或只按文件名随机切分，B仍可能把训练与验证连起来。可以把重复图的连通组作为划分约束；代价是大型模板组可能吞并许多不同事实。需要检查大组，选择代表样本时保留事实与版本差异，不能把共用页眉的所有型号都删成一个。

## 精确去重也有顺序依赖

同一段话带不同空白、页脚或URL时，先清洗再哈希更容易发现重复；但清洗会改变原始证据，原始哈希与规范化哈希应同时保存。去污染还要单独对照评测题族与答案来源。训练文本未与题目逐字重合，并不能排除共享题解或生成教师已见题的影响。

本轮仅核对原创文档精确唯一及实体组隔离；以上Jaccard和图是手算与设计，未声称运行大规模MinHash。

> **一句话听懂**：把相关样本放在同一个划分组里，再说明你真正留出了哪种变化。

> **到这里，你应该已经能听懂：**“新ID验证还共用模板，不能写成跨领域泛化。”
