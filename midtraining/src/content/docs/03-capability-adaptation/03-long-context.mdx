## 四件事需要一起改

| 对象 | 需要核对的内容 | 单独完成还缺什么 |
| --- | --- | --- |
| 输入/内存接口 | tokenizer、长度上限、attention实现 | 模型是否利用远处信息 |
| 位置表示 | RoPE频率/缩放或其他位置方案 | 新位置分布是否适应 |
| 数据 | 长文档、短文档保留、跨段依赖 | 任务是否需要真的读取远处 |
| 验收 | 长度、证据位置、干扰、任务类别 | 一个needle成绩不能代表全部应用 |

RoPE通过对query/key作位置相关旋转，让点积表达相对位置关系；它不提供一个自动保证任意远距离都可靠的开关。YaRN等方法处理扩展中的位置与attention尺度问题，仍需要对应模型和评测条件。[1][2]

## 长度变化还改了训练成本

对普通稠密attention，显式得分矩阵与S²有关。固定目标数B×S时，S翻倍、B减半，得分元素总数仍约翻倍；FlashAttention等实现减少显存读写或中间存储，不把所有attention数学计算都变成线性。

因此同token不必同墙钟或同FLOPs。长样本也可能只是多个短文档拼接，没有远距离依赖。不要用packing长度替代文档依赖跨度。

## 本地实验究竟做了什么

默认TinyBase从一开始就有64行可学习位置表，base只训练S32，后续比较S32/B4和S64/B2。两支从同一回放终点重新开运行，各消费6,144目标；这验证长度、计数和保存接口。

它没有RoPE、YaRN，也没有专门远距离依赖语料，所以不能把S64的loss改变称作长上下文能力提升。5.3给出应进一步做的证据位置、反事实和任务矩阵。

## RoPE为何与长度分布有关：只看一对二维坐标

在一个二维子空间，RoPE把query按位置m旋转，把key按位置n旋转。两者点积等价于一个由n−m决定的相对旋转；因此位置差会进入注意力分数。实际头维度由许多不同频率的二维子空间组成，并不是整段向量只用一个角度。[RoFormer §3](https://arxiv.org/html/2104.09864v5#S3)给出该构造。

```text
原query/key → 按各频段和位置旋转 → 点积/缩放 → 因果softmax
新距离范围 → 相对旋转分布变化 → 需要适配与任务验证
```

位置插值把更远距离压回较熟悉范围，可能同时改变局部距离分辨率；[YaRN §3](https://arxiv.org/html/2309.00071v3#S3)针对频段与attention尺度作处理。这里是机制说明，不提供可任意套用的theta或缩放值。

## 一个成本手算：相同token并不抵消长attention

假设普通attention，头数8，先B4/S1024，再B2/S2048。每头得分元素从4×1024²变为2×2048²，翻倍；乘8头后也翻倍。FFN的token数量却保持B×S=4096，所以两部分不会按同一比例变化。

[FlashAttention论文](https://arxiv.org/abs/2205.14135)的关键是分块和减少GPU存储层级间读写，避免显式保存完整得分矩阵；这是精确attention的实现改进，不能把上面的稠密数学关系改写成所有计算都与S线性。

## 真正有长依赖的数据是什么样

把64篇短标签文档串成一窗，长度增加但每篇答案可能只依赖邻近十几个token。更强的训练对象需要跨段关系：第一段定义型号版本，中间给例外，末尾要求按两者选择。还需保留短文，检查局部能力和后续训练的变化。关于长短混合，ProLong与SmolLM3报告并不提供一个对所有基座一致的最优结论；应在自己的协议下重做对照。

> **一句话听懂**：长度适配需要接口、位置、依赖数据和任务证据共同成立。

> **到这里，你应该已经能听懂：**“模型能接收64K，但我们只测过检索，没测多段推理。”
