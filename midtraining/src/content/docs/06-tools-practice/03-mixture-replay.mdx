## 领域分数变好，代价是什么

从同一base出发，继续看GX，全部改看NX，或保留25% GX回放。每支新增目标相同，才有机会把差异与源分布联系起来。

## 运行与固定项

```bash
python midtraining/examples/lab.py --out runs/my-midtraining
```

同一命令完成base、三支适配和长度接口实验。每个适配支路96更新，B4/S32、12,288目标、峰值lr0.001，AdamW重建；源配比为0/25/100%通用。每个seed的支路执行顺序在运行前由独立确定性seed打乱，记录在report中。

## 两个seed怎样读

seed42纯领域NLL4.115233→1.938298，通用1.574704→2.391756；回放的领域终点2.033484、通用1.615751。seed43纯领域终点领域1.766318/通用2.186506，回放为领域1.879007/通用1.418477。两组都呈现本例中的收益/回退取舍，不据此宣称25%是普遍最优。

继续通用训练的终点也必须保留：seed42领域5.060922/通用1.120583，seed43领域4.082616/通用0.933862。这条等预算控制说明，新领域证据与额外训练不是同一件事。

## 输出失败是结果的一部分

每条支路的4个领域续写探针均为0/4，未自然EOS，达到12个新字节上限。seed42回放对首条输入输出`tag: tag: ta`，seed43出现`useseseses t`等重复。全部原始token与文本随JSON发布，没有手工修成标签。

所以本例支持“领域文本拟合改善”和“回放改变了双集合取舍”，不支持“学会维修”“学会推理”或可靠输出标签。NLL是平均目标预测，重复生成仍可能失败。

## 成功条件、故障与下一步

产物含各seed终点.pt、源消费、逐点lr/NLL、固定窗口索引、生成与起始权重身份。检查纯领域12,288领域目标、回放9,216领域+3,072通用、通用支路12,288通用。

如果没有生成报告，先看非空out目录或依赖错误；若指标非有限，保留报错与状态，不修改报告。本轮已补做下文的答案区域NLL与候选评分；新模板和更多seed仍是未执行方案，不填成绩。

## 继续追问失败：只读旧检查点的新测量

这一诊断在原实验之后提出，用来分析失败，不改变原来的终点选择与主指标。原运行目录保留时执行：

```bash
python midtraining/examples/diagnose.py --run runs/my-midtraining --out runs/my-midtraining-diagnostics
```

固定每源前四个留出实体64–67，逐篇按真实完整前缀做教师强制。每篇33目标，切成前缀26、正确答案（四字母、标点、换行）及EOS7；分别累计104/28目标。不拼接跨文档，不同于原16×32固定窗口评测，绝对NLL不能直接与原表作差。

四候选评分是在同一个前缀下，对luma/nexo/pavo/sora各加标点、换行与EOS，累计候选全部目标logp，选择最大的序列。候选长度相同；它限制了可选答案，不等于让模型自由逐字节生成。各支仍只有1/4，不能将其宣传为修好了原0/4。

从新表只能说：领域/回放支路在这些真实前缀下，结构与关键答案区域都更容易预测；关键区域仍不足以形成正确映射排名或严格自由续写。它排除了“全部改善只发生在句式”这一强解释，却没有确认唯一失败成因。

## 怎样复核诊断没有暗中改模型

脚本核对原报告代码/数据身份、加载每个可信检查点后校验参数身份，不反向、不更新优化器；输出各条候选分数与新脚本SHA。`diagnostics-reference.json`保留两个区组全部八个状态及两类文本的结果。若没有原权重，先重跑lab；发布JSON足以阅读，不替代本地权重复跑。

[Hugging Face的PPL协议说明](https://huggingface.co/docs/transformers/perplexity)有助于理解为什么换前缀/窗口后是新测量；本表是本站实际诊断，不来自外部论文。

> **一句话听懂**：同预算比较两类分布，并让原始生成决定能否谈任务成功。

> **到这里，你应该已经能听懂：**“回放减少了本例通用回退，但严格标签生成仍没通过。”
