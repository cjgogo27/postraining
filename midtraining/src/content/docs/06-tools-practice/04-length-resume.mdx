## 单独运行12项检查

```bash
python midtraining/examples/verify.py --out runs/my-midtraining-checks
```

本轮12项实际PASS，包括实体组与唯一文档、真实字节/右移/EOS、未来输入不影响历史logits、位置越界拒绝、有效目标加权、新阶段计数、固定验证窗口与长度源配额。

最关键的恢复对照是8更新连续运行，与4更新保存、加载、再4更新比较：模型、AdamW、专用采样器、torch RNG、历史指标、源窗口账本、计数与起始身份精确相同。修改计划、实际数据、torch版本、world size或编码会被拒绝。

## 真正改一次代码再试

检查脚本在临时副本把`LR_MULTIPLIER = 1.0`改成1.01，再启动子进程读取原检查点，实际因训练代码身份不同而拒绝。它没有修改正式lab.py，也没有仅靠手工改报告中的一个哈希假装测试代码变化。

成功条件为检查脚本退出0、count12/statusPASS；如果只看到checkpoint文件能加载，不等于恢复对照成功。报告绑定最终训练源码SHA，复现前核对这一身份。

## 边界：这里没有测什么

这是CPU单布局、普通优化器更新边界的恢复。未做写盘中断、网络故障、分片状态、弹性world size或GPU数值一致性。原子替换文件的设计不等于故障注入已验证。

> **一句话听懂**：能力、长度接口和恢复状态是三组独立验收，分别给证据。

> **到这里，你应该已经能听懂：**“4+4和连续8步状态相同，但这不是跨卡数弹性恢复。”
