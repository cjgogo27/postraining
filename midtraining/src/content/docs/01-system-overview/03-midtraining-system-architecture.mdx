## 一份文档怎样进入训练

原文是`Unit NX00 uses Z0. Z0 tag: luma.`。NX设备及标签均为教学虚构，不能用于真实维护。来源审核给它文档ID、实体组ID、版本和许可；清洗保留术语关系，去重后先按组划分训练/验证，再编码成窗口。NX00属于训练组，NX64–79只用于验证，不能混回训练。

本地小模型使用**真实UTF-8字节编码**：0–255为字节值，EOS另定义为256。取其中`Z0`加EOS这个短片段，可得到：

```text
sequence  = [90, 48, 256]    # 真实字节Z、0，另加本实验EOS
input_ids = [90, 48]
labels    = [48, 256]        # 右移一位，分别预测0与EOS
loss_mask = [1, 1]
可见范围：位置0只见[90]；位置1见[90,48]，不能看未来标签
```

这只是展示右移的片段，不是整个手册的分词结果。对真实公开基座，应使用其绑定的tokenizer与特殊token，不能把本实验字节ID当作SmolLM2词表ID。

## 接口表：接收什么、何时运行、凭什么检查

| 职责 | 接收并执行什么 | 交出什么 | 执行时机 | 检查依据 |
| --- | --- | --- | --- | --- |
| 任务与验收 | 基座、目标任务、回退容忍度 | 冻结题目与协议 | 开始前及新方案评审 | 题目/评分器/模板版本 |
| 数据准备 | 来源文本、清洗、去重、组划分 | manifest与各源唯一数据量 | 数据版本变化时 | 文档与组ID、许可、污染检查 |
| 采样与编码 | 配比、token预算、EOS/窗口约定 | input/labels/mask、源消费账本 | 每个微批次 | 实际目标计数、窗口索引、边界 |
| 模型前向 | 输入与因果可见范围 | logits与逐目标loss | 每个微批次 | 形状、有限值、未来不可见 |
| 反向与更新 | loss和全局有效分母 | 梯度、Adam状态、新权重 | 累积到约定边界 | 归约、同步、裁剪、成功更新 |
| 保存与恢复 | 权重、优化器、随机与数据状态 | 有身份的完整检查点 | 约定的提交边界 | 哈希、配置、版本、恢复对照 |
| 独立评测 | 指定检查点和固定窗口/任务 | 收益、回退和失败样本 | 阶段性，可另机执行 | 固定协议、样本与模型身份 |

表中不写固定毫秒数：离线清洗、微批次、优化器更新与异步评测没有同一种运行节奏。框架可以承担多项职责，硬件也能被不同模块共享。

## 从logits到梯度：改变的是哪些数

默认微批次B=4、长度S=32、字节词表V=257，输入/标签形状为`[4,32]`，模型logits为`[4,32,257]`。每个目标位置把257个分数经softmax变成概率，再取正确目标的负log概率。

例如两个位置的目标概率为0.1与0.2，其loss为2.3026与1.6094，平均约1.9560。这是独立手算，不是本地模型实测。反向传播求出loss对参数的梯度；累积与必要的跨rank同步后，优化器使用梯度和自己的历史状态更新参数。

默认实验所有右移目标有效，4×32=128目标/更新；96更新消费12,288目标。25%通用回放对应3,072通用、9,216领域目标。这是重复消费计数，不等于唯一语料规模，也不包含评测和重复前向等全部计算。4.2展开padding、累积与分布式后的分母。

> **第一次阅读理解到这里即可。** 下面用异常把数据、计划与状态接起来；恢复实现细节放在4.6与6.4。

## 两种反馈不要混为一种闭环

训练loss经反向传播更新权重，是数值优化反馈；看到领域收益与通用回退后，决定改配比或回退，是实验决策反馈。后者可能产生一个新的运行计划，不是对一个评测分数直接反传。

阶段验收还可能包括固定SFT探针：同样的后训练协议下，哪个中训练起点更适合后续任务？这会增加成本，也需要独立版本。主预训练、中训练与后训练没有唯一必须串行的配方，项目的分支和名称应按原材料解释。[1][2]

## 恢复后loss跳变：按证据排查

假设恢复前领域NLL约1.0，恢复后首个记录变成2.0。先别据一个标量断定遗忘：

| 观察证据 | 候选解释 | 最小确认 |
| --- | --- | --- |
| 新旧manifest或tokenizer不同 | 换了语料/编码；loss不能直接续线 | 固定窗口、标签与哈希逐项比对 |
| 源消费从75%领域变为100%领域 | loader或回放计划重置 | 对照已提交源账本与下一批索引 |
| 学习率从衰减末尾回到峰值 | 调度计数未恢复或错误新建阶段 | 打印下一步lr、成功更新数、计划身份 |
| Adam一二阶状态缺失 | 只加载权重却称完整恢复 | 比较优化器状态与连续运行的一步更新 |
| 采样器/随机状态或rank布局改变 | 下一批不同，或同步语义变化 | 固定batch对照梯度；再核对数据分片和world size |
| 窗口完全一致仍跳变 | 数值/权重/日志归约可能不同 | 相同CPU环境逐层核对logits与分母 |

本地严格恢复实际检查代码、数据、计划、PyTorch、world size与编码身份，恢复模型/Adam/专用采样器/随机状态。它只承诺当前CPU单布局和更新边界，不能把拒绝不同world size包装成已经实现弹性迁移。

## 共用基础设施让交接可追溯

计算与显存承载前后向；存储与加载提供稳定样本流；通信安排梯度或参数交接；调度决定何时拿到资源；日志、配置与版本把“看上去相同”的两次运行变成能比较的记录。PyTorch、DeepSpeed或Megatron是实现工具，不是固定的业务功能层。

> **一句话听懂**：沿文档、窗口、张量、梯度、完整状态与评测证据追踪变化，才知道新权重是否值得交付。

> **到这里，你应该已经能听懂：**“先确认恢复的是同一份数据与优化状态，再解释这次loss跳变。”
