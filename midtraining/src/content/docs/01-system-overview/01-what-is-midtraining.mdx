## 从一本设备手册说起

团队希望模型阅读维修记录，识别型号、故障码及其对应术语。模型本来能续写一般文本，却把内部码Z0与Z1混在一起。把所有手册塞进一次提示，既占上下文，也没有回答“模型是否已经学到这套文本分布”。

## 先看改变什么，再看阶段叫什么

从已有权重继续学习一批针对性数据，补领域、代码/数学或上下文等能力，并准备后续适配，这类工作常被称为**中训练（mid-training）**。它不是每个项目必经的标准步骤，也没有统一的token量或loss定义。

| 工作 | 重点改变什么 | 不能仅靠它确认什么 |
| --- | --- | --- |
| 主预训练 | 广泛文本上的基础建模能力 | 已符合特定业务验收 |
| 本书的中训练 | 针对性数据分布与能力准备 | 已会遵守所有指令或可靠调用工具 |
| SFT/偏好/RL等后训练 | 指定监督下的输出行为与策略 | 新领域知识永远充分、不会回退 |
| RAG检索 | 推理时提供可更新的外部证据 | 权重已经吸收全部资料 |

同一种交叉熵也能出现在预训练、中训练和SFT中；要看数据、监督位置、起点与验收，而不是用loss名字给阶段贴标签。RAG与权重训练可结合。资料频繁变更、必须追溯来源时，先做好检索和引用可能更合适；术语分布长期稳定且有受控数据时，再检验继续训练是否值得。

## 项目之间的边界并不相同

SmolLM3把长上下文和推理适配称为mid-training；Olmo 3则在其base构建中分别列出midtraining与long-context extension。这里的差异应保留，而不是替两者统一改名。本书把这些针对性继续训练放在同一张生命周期地图中，逐项标注项目自己的名称。[1][2]

中训练也不保证“只激发现有能力”：权重可能学习新关联，可能忘掉旧模式，也可能仅记住模板。默认小实验使用虚构NX设备码与通用GX文本，目的就是把这些变化变成可核对的记录。

## 不靠训练时长，靠四个字段识别阶段

设团队交来两份运行记录：A从通用base出发，用设备说明全文做因果预测；B也从base出发，把相同说明整理成问答，只在回答位置监督。两份都调用AdamW，也都可能训练一天，优化问题仍不同。

```text
阶段身份 = 起点检查点 + 数据分布/形式 + 优化目标/mask + 下游验收
A：base → 手册全文 → 全目标next-token → 域内NLL与任务/保留检查
B：base → 问题/示范 → 回答位置CE → 指令行为与内容检查
```

先记录这四项，阶段名才有可复核含义。不能看到“instruction”字段就认定已经完成行为对齐，也不能看到普通交叉熵就认定还处于主预训练。

## 中训练为什么可能成为“过渡台阶”

通用网页、代码仓库、解题过程和最终问答的文本结构不同。直观上，先让模型接触目标附近的分布，再接受较窄的后续监督，可能减少一次过大的迁移。这个解释包含一个待检验命题：**相同后续训练协议下，新起点是否更好用**，而不只是中间检查点的loss是否更低。

[Liu等的中训练研究，2026年v2，§2与§5](https://arxiv.org/html/2510.14865v2#S2)把混合通用与专门数据的中间阶段作为自己的研究定义，研究分布桥接。本书范围更宽，另纳入纯领域与长度适配作对照；不要把论文的操作定义提升为统一行业定义。

阅读后续章节时，可以把“做中训练”改写成一句具体话：我们从哪个base，用哪些新分布、多少有效目标，换来哪些可测变化，并准备交给哪种下游协议。

> **一句话听懂**：先说明起点、数据、目标和验收，再使用“中训练”这个阶段名。

> **到这里，你应该已经能听懂：**“这是从base继续做领域适配，完成后还要单独验收并做SFT。”
