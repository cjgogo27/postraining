> **系统位置**：把语言建模指标和实际输出共同提交给[1.3验收](/postraining/midtraining/01-system-overview/03-midtraining-system-architecture/)。

## 一个需要保留的实际负结果

seed42纯领域支路把固定领域S32 NLL从4.115233降到1.938298。面对固定标签前缀，仍可能输出`tag: tag: ta`并达到12字节上限，四个生成探针都没通过严格验收。

<SectionQA id="5.2" mode="ask" />

这不是要把NLL判成无用，而是它与任务完成检查不同对象。领域词法和结构学得更顺，仍可能没生成正确标签；不能把曲线进步改写成“已经理解维修手册”。

## 协议影响分数，也影响解释

本实验要求生成自然EOS且原始文本精确等于规定标签（含标点与换行）。如果改成“只要包含luma就对”，输出`luma...sora`也可能被计对；如果对两次实验使用不同抽取器，分数差未必来自模型。

| 一份前后对照应包含 | 为什么需要 |
| --- | --- |
| 固定输入与期望输出 | 保持任务与难度一致 |
| 原始token、文本和结束原因 | 发现重复、截断与抽取假象 |
| 内容/格式/引用分项 | 不把格式修复说成知识提升 |
| 通用保留探针 | 发现目标外回退 |
| 固定评测预算与采样 | 避免更多候选带来表面优势 |

## 成对比较，仍需保留外推边界

每个seed区组用同一个base，三种方案分别评同一组窗口和原始生成；比较应在区组内看变化，再列两个seed，而不是把每个检查点当一个独立模型重复。

产品交付应增加独立的真实任务test、故障类型和时间分布。本站NX数据、四个标签和四个生成探针仅提供机制示例；GX文本NLL也不是完整通用能力基准。本轮不会通过换输出格式、选更好seed或改成功规则美化失败。

> **一句话听懂**：语言建模、任务生成、格式和保留能力要各自有证据。

> **到这里，你应该已经能听懂：**“NLL进步属实，但这四条严格生成仍是0/4。”
