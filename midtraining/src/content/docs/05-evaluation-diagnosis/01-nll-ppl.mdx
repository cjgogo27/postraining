## 同一个2.0，为什么可能不是同一个难度

一个模型按字节预测，另一个按BPE预测；一个只评答案，另一个评全文。把两者loss2.0直接比较，忽略了预测单位与条件范围。

<SectionQA id="5.1" mode="ask" />

若用自然对数、对有效目标求平均负logp，PPL为 `exp(NLL)`。例如NLL2对应PPL约7.389；它反映这个条件预测任务的指数化平均损失，不是错误率或平均候选数量的直接测量。

| 比较前要固定 | 变化以后为什么有问题 |
| --- | --- |
| tokenizer与特殊token | 一个token对应的文本量不同 |
| 文档、窗口索引与长度 | 条件信息与难度不同 |
| loss mask与分母 | 被测目标集合不同 |
| EOS、跨文档与截断 | 预测边界不同 |
| eval模式与数值实现 | dropout或计算路径可能不同 |

## 把窗口身份和分母发布出来

默认lab对通用/领域分别固定16个S32验证窗口，各512目标；S64则8窗口、也各512目标。索引与stream哈希随报告保存。两个长度各自固定比较，不把条件范围变化后的NLL当成完全相同任务。

这些窗口可能重叠，因此512是累计评测目标，不是512个独立样本或唯一字节数。全体目标NLL以总负logp/总有效数计算，不等权平均长度不同的窗口均值。

## 分项指标比一个总分更能定位

若50%通用+50%领域的合并NLL下降，仍可能遮住通用回退。分别列NLL、任务输出、模型身份与源消费；跨论文或换tokenizer时，可以另定义可比的文本归一化指标，但要明确计算协议，不能凭PPL值排序所有模型。

本文NLL算例是公式解释，实际数值见6.2–6.4；没有引用公开模型PPL当本站成绩。

## PPL的平均不是先取指数再平均

假设两个集合各100目标，NLL分别1和3，合并NLL为2，合并PPL为exp(2)≈7.389。若先计算两份PPL再平均，得到`(exp(1)+exp(3))/2≈11.402`，不是同一个指标。位置数不等时还应先按有效目标加权NLL。

## 长文评测有两种不同的“窗口”

独立分块把长文切成互不借前缀的片段，块首缺少原本可用的历史；滑动窗口用重叠前缀提供条件信息，只对新进入的目标计分。若同时对全部重叠目标反复计分，指标又变成另一种加权任务。

[Hugging Face官方PPL讲解](https://huggingface.co/docs/transformers/perplexity)讨论固定上下文模型与滑窗的区别。借用协议时必须固定stride、最大长度、首尾处理和有效分母。该页面随Transformers更新，本书没有直接复制其中动态版本代码。

默认lab选择固定窗口集合并允许重叠，对窗口里的所有目标计分；报告说的是该固定任务，不是整段验证流逐token恰好一次的PPL。新增整文档区域诊断又是另一个任务，不能拿它的绝对NLL与原512目标窗口数直接相减。

## 若必须跨tokenizer比较，先定义新单位

可以把同一原文的总负log概率除以UTF-8字节数，再除ln2得到bits/byte；但仍要统一起止符、文本规范化、条件上下文与计分覆盖。它没有自动消除所有协议差异，也不等于业务正确率。本站没有新增跨tokenizer排行榜。

> **一句话听懂**：PPL只有在预测单位、条件和目标集合可比时才有直接比较意义。

> **到这里，你应该已经能听懂：**“两条曲线先固定窗口与分词器，再看NLL差。”
