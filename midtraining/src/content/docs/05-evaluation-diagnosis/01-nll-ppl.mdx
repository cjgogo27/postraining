## 同一个2.0，为什么可能不是同一个难度

一个模型按字节预测，另一个按BPE预测；一个只评答案，另一个评全文。把两者loss2.0直接比较，忽略了预测单位与条件范围。

<SectionQA id="5.1" mode="ask" />

若用自然对数、对有效目标求平均负logp，PPL为 `exp(NLL)`。例如NLL2对应PPL约7.389；它反映这个条件预测任务的指数化平均损失，不是错误率或平均候选数量的直接测量。

| 比较前要固定 | 变化以后为什么有问题 |
| --- | --- |
| tokenizer与特殊token | 一个token对应的文本量不同 |
| 文档、窗口索引与长度 | 条件信息与难度不同 |
| loss mask与分母 | 被测目标集合不同 |
| EOS、跨文档与截断 | 预测边界不同 |
| eval模式与数值实现 | dropout或计算路径可能不同 |

## 把窗口身份和分母发布出来

默认lab对通用/领域分别固定16个S32验证窗口，各512目标；S64则8窗口、也各512目标。索引与stream哈希随报告保存。两个长度各自固定比较，不把条件范围变化后的NLL当成完全相同任务。

这些窗口可能重叠，因此512是累计评测目标，不是512个独立样本或唯一字节数。全体目标NLL以总负logp/总有效数计算，不等权平均长度不同的窗口均值。

## 分项指标比一个总分更能定位

若50%通用+50%领域的合并NLL下降，仍可能遮住通用回退。分别列NLL、任务输出、模型身份与源消费；跨论文或换tokenizer时，可以另定义可比的文本归一化指标，但要明确计算协议，不能凭PPL值排序所有模型。

本文NLL算例是公式解释，实际数值见6.2–6.4；没有引用公开模型PPL当本站成绩。

> **一句话听懂**：PPL只有在预测单位、条件和目标集合可比时才有直接比较意义。

> **到这里，你应该已经能听懂：**“两条曲线先固定窗口与分词器，再看NLL差。”
