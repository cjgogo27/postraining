## 现场问题

同一对回答交换A/B位置后，裁判的偏好跟着位置走。团队却把单次票数当作稳定胜率。

> 怎样判断裁判是在评质量，而不是位置或措辞？

<SectionQA id="5.2" mode="ask" />

## 裁判也是一个需要验收的模型

LLM-as-a-judge可用于开放式任务，但需要冻结裁判权重/服务版本、rubric、输入模板、解析和采样设置。原始研究讨论过位置、冗长、自我偏好等偏差及与人类评价的一致性；不能把任何模型裁判自动当真值。[1]

一个最小协议：同题同候选，分别以A/B和B/A顺序评分，映回真实候选身份，再记录一致、冲突与tie。假设第一轮选A，交换后仍选显示位置A，实际选的是另一回答；这是冲突，不应默默计两张支持同一模型的票。

## 评分表需要什么

| 字段 | 用途 |
| --- | --- |
| prompt与候选哈希 | 固定比较对象 |
| presentation_order | 识别位置影响 |
| rubric与judge版本 | 复核评分变化 |
| 原始输出 / 解析状态 | 发现无效裁判回答 |
| 分维得分 / tie / abstain | 保留不确定性 |

先在小规模人工审阅集上校准，再按语言、长度和任务分层检查。用同一模型生成数据、训练奖励又做最后裁判，会增加共同盲区，应明确证据依赖。

## Elo分不是绝对能力百分比

排名模型可把成对结果汇总为分数；例如假设采用 `P(A胜)=1/(1+10^((R_B−R_A)/400))` 的打分约定，A高400分时映射为约90.9%。这是模型映射的手算，不是本项目测得的胜率。它不是数学正确率、概率校准保证或跨不同榜单可直接相减的单位。对手池、采样、平局和时间变化都会影响解释。

少量对局不应给出虚假的精确排名。报告对局数、分层、区间或稳定性，明确缺失对局如何处理。本项目未调用外部裁判、收集人工票或拟合Elo；这些是可执行的评测方案与手算，不是本站实测榜单。

> **一句话听懂**：裁判、展示顺序和聚合模型都是评测系统的一部分，也需要独立检查。
