> **系统位置**：接收冻结权重与题集，固定模板/解码/评分，交出可配对的报告。 [回到1.3总图](/postraining/01-system-overview/03-posttraining-system-architecture/)。

## 现场问题

新模型在一张榜单上提高了5分，但旧模型用的是短提示，新模型多了示例和更长输出预算。

> 分数变化来自权重，还是评测条件？

<SectionQA id="5.1" mode="ask" />

## 一个分数至少绑定五种身份

模型/adapter、题集划分、提示/模板、生成协议、评分/抽取器版本共同决定结果。基线和新模型在同一题上运行，再记录配对的成功/失败，比只比较两个总体数字更容易定位变化。[1]

| 项目 | 本地语言模型实验约定 |
| --- | --- |
| 题目 | 固定23条val、12个来源组 |
| prompt | ASCII `Q:a+b\nA:`，无额外示例 |
| 解码 | greedy，最多4个新字节token |
| 成功 | 自然EOS且规范答案完全相同 |
| 补充指标 | 回答NLL、固定pair排序、原始生成 |

这里只设一个val用于机制观察，没有独立产品test。不同任务有不同可接受输出，不应把纯数字协议推广到所有聊天回答。

## 抽取器也能制造提升

假设两条输出为`5`和`答案是5。`，题目要求纯数字。严格格式评分为1/2；若事后改成“提取最后一个数字”，可能变成2/2。**这是人工构造的评分示例，模型权重并未变化。** 报告必须说明评分器变化，不能称模型提升50个百分点。

## 看配对失败，而非只看均值

假设20题中，A对8题，B对10题，其中B修复4题又丢掉2题；两分均值掩盖了不同错误类别。分层记录格式、答案、截断与拒答，必要时对同一来源组整体分析。共用模板题不一定独立，不能把每token当作独立样本做显著性声明。

## 别让测试变成选择器

在同一个val上试十种学习率、选最高分，再报告这一分，会引入选择偏差。保留全部运行与预定终点，或明确dev选型后另用test。本项目固定展示SFT300/DPO120终点，即使DPO80步曾有2/23正确，也不偷换为最终结果。多种子和更广任务是后续实验设计，本轮没有执行。

> **一句话听懂**：先固定可比较条件，保存配对输出，再解释分数变化来自哪里。

> **到这里，你应该已经能听懂：**“抽取器改了，先别把分数变化归给权重。”
