## 现场问题

接收方拿到adapter或权重，套上另一份模板，得到不同输出；发布说明却只有“后训练完成”。

> 什么交付包能让别人判断结果是否被正确复现？

<SectionQA id="6.5" mode="ask" />

## 训练恢复包与使用包分别说明

恢复包包含优化器、参考策略、随机状态和进度；使用包通常只需推理所需权重/adapter、基座身份、tokenizer、模板和生成配置。不要把一个可加载文件当成完整交付，也不要为了推理强迫接收方加载含Python复杂对象的训练快照。

| 交付物 | 要回答的问题 |
| --- | --- |
| 权重与结构配置 | 是哪个模型、更新了哪些参数 |
| 基座/adapter关联 | 适配哪份基座、哪些模块 |
| tokenizer与模板 | 角色和结束符怎样编码 |
| 训练记录 | 什么数据、反馈、代码与计划产生 |
| 评测协议与输出 | 同一条件下能否复核分数 |
| 模型卡与局限 | 能支持什么用途、哪些未验证 |

本项目发布的是教程、源码和小规模运行证据，不将训练权重包装成可用的生产助手。大快照保留在runs目录，提交的JSON足够查看配置、指标和原始输出，重跑命令能重新生成权重。

## 一个合格的结果表述

可以说：“在固定23条共用模板验证题、greedy最多4字节并EOS协议下，SFT300步1题严格正确，DPO120步0题；16项机制与边界恢复检查通过。”不能改成“后训练显著提升数学推理、安全与生产稳定性”。有限动作RL的12/12也必须带上四候选、训练题和表格策略限制。

## 接收方的一次最短验收

核对代码/数据身份→准备Python环境→生成同份数据→跑SFT及DPO→检查计数/输出→跑verify→对照已发布JSON。计时可随机器变化，不要求复制本机秒数；数值对齐只在声明的软件与条件范围内解释。

如果生产项目改用真实基座、LoRA、训练框架或采样引擎，应建立新的数据/配置/评测记录，重新验证掩码、参考策略和恢复。不能因为使用了相同算法名字就继承本教程的验证结论。部署引擎与服务SLO不是本书的实现范围，这里只定义后训练产物的交接接口。

> **一句话听懂**：交付的不只是权重，还包括让接收方理解并复核它的条件与证据。
