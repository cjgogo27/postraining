## 现场问题

完整语言模型RL需要许多采样和评分接口。先把回答空间缩到四个候选，能否看清奖励怎样改变动作概率？

> 缩小后的实验保留了什么，又删掉了什么？

<SectionQA id="6.3" mode="ask" />

## 这是表格策略，不是语言模型GRPO

```bash
python examples/rlvr.py --out runs/rlvr
```

12个固定加法prompt，每题4个候选串：规范答案、偏一错误、尾部多0、带前缀格式。候选顺序按题轮换。策略是 `[12,4]` 可训练logits，共48参数，没有tokenizer、Transformer或自由生成，也没有未见题泛化。每题能直接枚举正确候选概率，便于与采样奖励区分。

## 一轮实际执行什么

每轮冻结当前行为logp，每题从完整categorical分布有放回采8次，得到96个动作。规范串比较给0/1奖励，以总体标准差构造组优势；同一批做2次Adam更新，clip区间[0.8,1.2]，精确 `KL(policy||uniform)` 系数0.02，lr0.05。随后刷新行为策略开始下一轮。

| 次数与指标 | 本轮实际值 |
| --- | --- |
| rollout轮数 | 80 |
| optimizer更新 | 160 |
| 累计采样动作 | 80×12×8=7680 |
| 初始正确候选期望概率 | 0.25 |
| 最终正确候选期望概率 | 0.99090046 |
| 最终训练题贪心选择正确率 | 12/12 |
| 最后一轮恒定奖励组 | 11/12 |
| 最后一轮actor版本 | 158 |

![有限动作策略的期望奖励和每轮采样奖励，非语言模型泛化结果](/postraining/figures/rlvr-results.svg)

期望概率来自枚举当前四动作分布，不是某轮采样成功率；最后一轮采样奖励均值约0.98958，也不是同一个量。最后一轮两个epoch的clip fraction都为0；说明代码包含剪裁不代表该轮实际触发剪裁。正/负优势的剪裁手算另有测试。

## 怎样判断运行合理

会得到report.json与latest.pt，记录每轮actor版本、old概率样例、奖励、优势、恒定组、KL、clip fraction与更新数。检查概率有限且归一化、计数一致、参考KL定义不变。奖励上升不要求所有轮次单调；采样和KL约束可产生波动。

本项目已运行默认80轮及8轮边界恢复验证，完整记录见 `examples/results/rlvr-reference.json`。若全组优势为0，检查原始奖励是全成功、全失败还是验证器常数；若错误格式也得1，先查验收协议。

## 结论边界

这是带可验证奖励的有限动作contextual bandit，采用组优势与剪裁代理目标，只演示接口机制。每题独立参数会记住这12题，所以12/12不代表学会加法推理。语言模型还需要逐token old logp、可变长度mask、采样引擎、权重同步等；本轮没有把这些缺省机制算成已完成。

> **一句话听懂**：用有限动作看清奖励与概率更新，再明确它没有证明语言生成或泛化。
