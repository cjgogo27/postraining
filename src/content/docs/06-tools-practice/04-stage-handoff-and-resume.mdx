> **系统位置**：接收阶段权重或完整快照，区分新运行与恢复，交出身份一致的状态。 [回到1.3总图](/postraining/01-system-overview/03-posttraining-system-architecture/)。

## 现场问题

你想从SFT进入DPO，同时又要演练中断恢复。两个命令都加载权重，却不应该继承同一套状态。

> 什么时候是新运行，什么时候才是延续原来的更新轨迹？

## 两种加载有不同承诺

`--init`仅继承匹配架构/编码的权重，新建优化器、随机流和计数；在DPO新阶段还冻结参考权重。`--resume`恢复同一阶段的当前参数、参考参数、优化器、计数与随机状态，要求同数据、同关键计划、同训练代码、同PyTorch和world_size=1。

| 状态 | 新DPO阶段 | 严格DPO恢复 |
| --- | --- | --- |
| 当前权重 | 来源SFT权重 | 已更新到暂停边界的权重 |
| 参考权重 | 冻结为来源SFT | 原先冻结参考，不重建成当前权重 |
| AdamW与步数 | 新建、从0开始 | 保留矩与更新计数 |
| 抽样随机状态 | 新运行seed规则 | 恢复暂停时状态 |
| 数据和代码 | 记录新身份 | 必须与原运行相同 |

一个常见错误是恢复DPO时把当前模型复制成新参考；这样即使权重load成功，目标已经改变。本项目保存reference本身，恢复不依赖再读取原始SFT文件。

## 自己演练更新边界暂停

```bash
python examples/train.py --data runs/data --out runs/paused --steps 300 --stop-after 100
python examples/train.py --data runs/data --out runs/resumed --steps 300 --resume runs/paused/latest.pt
python examples/verify.py --out runs/checks
```

两次总计划都为300，提前停止只改变本次进程终点。SFT/DPO的代码身份同时绑定规范化 `postcore.py` 与 `train.py`；改实际学习率代码1.01倍也拒绝。Git版本是来源管理的一部分，哈希不是安全签名或跨硬件逐位保证。

## 实际验证覆盖到哪里

原有16项检查覆盖：真实字节/shift/EOS、mask不计prompt/padding、因果可见范围、变长回答logp求和、DPO手算与梯度方向、组标准差/常数奖励、正负优势clip、验证器反例；SFT和DPO各8步连续对比4步暂停恢复完全一致，参考未变且新阶段优化器重置；改变计划、PyTorch/world size、实际代码、数据均拒绝；有限动作RL在8轮连续与4轮保存恢复也完全一致。每轮实际重跑范围见VALIDATION.md。

语言模型在**optimizer更新边界**保存；有限动作RL在**完整rollout轮边界**保存。没有保存更新一半的梯度或异步在途轨迹。上述恢复未测试写盘中断、rank崩溃、CUDA、DDP恢复、分片和多机，不称生产容错验收。只能加载可信检查点；完整状态采用Python序列化。

## 串起整条生命周期：一项独立的教学夹具

为了把1.3和5.4的职责落到可检查产物，新增以下命令。先完成6.1的CPU环境；默认不需要网络、模型下载或生产平台：

```bash
python examples/posttraining_lifecycle.py --out runs/lifecycle
python examples/posttraining_lifecycle.py --ddp --out runs/lifecycle-ddp
```

第二条额外启动**两个真实本机Gloo进程**，需要PyTorch的distributed/Gloo支持及本机回环端口；第一条保持单进程。每次用新目录。不是通过torchrun部署生产worker，也没有GPU性能测试。

### 一张12参数表格怎样跨阶段交接

夹具仅4个上下文、每个3个离散候选，共12个logits，没有tokenizer、自然语言生成或未见任务。选定SFT→DPO→RL作为一种说明路径，各阶段新建AdamW、计数与专用采样Generator；目标与冻结参考明确切换。这不表示所有后训练必须按此顺序。

| 实际阶段 | 消费与更新 | 验证的交接 |
| --- | --- | --- |
| SFT | 4次更新，每次4个标签，消费16个动作示范 | 新DPO初始参数等于SFT终点，AdamW状态为空 |
| DPO | 3次更新，每次4个pair，消费12个pair | 参考固定为SFT终点，新RL继承DPO参数并重建状态 |
| RL | 2轮，每轮4上下文各有放回采4次=16动作；每批2次更新 | 32个采样动作、4次更新、行为版本0/2，发布版本2/4 |

模拟本地worker复制采样快照后核对权重哈希；复用同批时old logp保持不变。batch准入拒绝重复提交、过旧/未来版本、评分身份不匹配、超时状态和有效计数为0。年龄上限2是夹具协议，不是生产推荐值；没有声称所有允许范围内数据都无偏。

RL第一轮提交后，实际写入并原子替换一个完整检查点；连续完成第二轮，与重载后重新采第二轮对比。参数、AdamW、参考、专用Generator、动作记录、提交清单与计数**精确相同**。这里只覆盖完成轮边界；没有模拟崩溃或中途写盘失败，也没有dropout/全局随机路径的恢复保证。

### 固定PPO张量的单进程/两rank对照

这是独立于12参数表格的数值子例：策略logits形状`[2,4,3]`，两条固定窗口分别有2和4个有效位置，旧概率、优势、mask与参考口径都固定。单进程对6位置归约；两rank各处理一条，按默认DDP平均语义对本地loss总和乘2/6。

实际CPU FP64运行中，两rank与单进程的梯度及一次SGD更新参数的最大绝对差均为0；验收容差atol=1e-12、rtol=1e-10。反例“先各按局部均值再平均”的梯度最大误差约**0.05694594**。这说明分母会改变参数更新；不等于完整LLM PPO、GPU通信或跨硬件逐位保证。

### 产物、成功条件与失败边界

实际`--ddp`报告发布在`examples/results/lifecycle-system-reference.json`，含源码身份、配置、阶段计数、拒绝原因、恢复记录与两rank误差。运行目录另有`checkpoint.pt`及rank数值文件。成功条件为退出码0、status=PASS、10项检查满足断言；没有把“奖励变高”设为成功门槛。

输出目录已存在时改用新目录；Gloo或回环端口不可用时先运行单进程并记录限制，不能把未启动的两rank检查写成通过。本次有Windows地址族连接重试提示，最终两个进程完成。该夹具是**真实执行的生命周期/数值验证**，不是完整后训练能力实验。

## 生产系统还须保存什么

| 交接边界 | 额外状态 | 如果只存权重会怎样 |
| --- | --- | --- |
| actor/critic更新 | 各自优化器、调度/成功次数、精度scaler | 有一个跳过更新时仍可能被错误计数 |
| 采样/评分队列 | 请求/attempt、实际行为概率、评分状态与版本 | 重复提交或混入另一规则的分数 |
| 长轨迹/工具环境 | 片段版本、上下文、工具与环境快照 | 无法解释中间状态，更无法保证重放 |
| 分片保存/发布 | 完整manifest、各分片完成状态、接受版本 | 未完整写入或未全部加载也可能被当作有效版本 |

是否保存所有在途工作取决于恢复承诺；也可以明确丢弃并重新采集，但要记录损失的工作和新的随机/数据进度。优化器更新完成与checkpoint提交完成是不同事件。单文件`os.replace`的夹具不能证明多文件分片快照已经具备原子提交语义。

> **一句话听懂**：新阶段重建状态，严格恢复延续状态；参考策略也是不能丢的训练状态。

> **到这里，你应该已经能听懂：**“继续原运行要恢复参考和随机状态，新阶段则另建优化器。”
