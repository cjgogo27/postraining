## rollout是一份带身份的经历

**rollout**记录在指定条件下生成的动作序列。对语言模型，一次动作通常是一个token，状态是prompt和已生成前缀。至少保存prompt/response ID、动作token、有效mask、生成结束原因、行为策略版本、生成设置、old logp和奖励版本。只有文本不够复核概率比。[1][2]

```text
prompt_id → actor_version → response_ids / old_logp / eos_or_truncated
          → verifier_version / reward_status → training_batch_id
```

旧策略对应实际行为分布，本轮复用轨迹时保持固定；当前策略参与更新，下一轮采样再刷新。参考策略可长时间冻结，不应随着每次更新覆盖。日志要区分“rollout轮数”“优化器更新次数”和“权重同步次数”。

## 从单轮回答扩展到工具轨迹

工单助手这次没有直接拿到订单状态。下面是一条人工设计的完整经历，不是已训练模型的实测输出：

| 次序 / 来源 | 内容 | 在策略训练里的角色 |
| --- | --- | --- |
| 0 用户 | 订单A17发货了吗？ | 条件，通常不直接计策略loss |
| 1 assistant | 调用`lookup_order({"id":"A17"})` | 模型动作；调用名与参数序列要学习 |
| 2 tool | `{"id":"A17","status":"shipped"}` | 环境观察；通常不当作assistant目标 |
| 3 assistant | 订单A17已发货。 | 模型动作；最终回答要学习 |
| 4 验收器 | 订单正确、状态正确、未编造 | 终端任务奖励与评分状态 |

这里一条轨迹含两个assistant动作片段。后面的回答可以注意到工具返回，但常见的策略目标只对assistant动作token计loss；tool正文不是模型自己采样的动作，不能把它也填进old logp比值。调用控制标记和结束token按实际模板确定，不能仅凭消息role粗略猜位置。SFT同样可以在两个assistant片段上提供示范。

### 延迟奖励怎样回到前面的决策

如果查错订单，最后文字再流畅也无法完成任务。终端奖励可以经回报估计作用到此前的动作；简化的无折扣蒙特卡洛回报可把相同结果传到两个动作片段，再减各状态基线。它并不自动知道失败源于查单、参数还是读错返回；critic、过程反馈和错误分类各提供不同帮助，不能把终端1分当作每一步都已被证明正确。

训练接口还要保存调用ID、参数、返回、异常/超时、重试、动作mask及行为版本。只读查询的本地模拟应固定订单表；有状态环境的重放还要绑定初始状态与变更记录。先看5.5如何固定证据，再做真实工具训练。本轮只核对消息到动作mask的教学夹具，没有运行工具型语言模型RL。

可运行`python examples/verify_teaching.py --out runs/teaching-checks`，得到`tool-trace.json`与检查报告。夹具用原创字节消息边界，不是SmolLM2的聊天模板；逐位置验证用户/工具内容不计动作loss、两个assistant片段与其EOS参与目标，并正确右移。这里不执行外部工具。

> 能分出“谁决定动作、谁返回观察、奖励何时出现”即可继续；old概率与采样分布是后续实现查阅。


## 一个简单版本算例

第k轮用版本v采8个候选，保存old logp；在同一批上更新两次后得到v+2，再启动下一轮。第一次更新前，在相同模型、输入和概率定义下ratio应约为1；第二次可以偏离。若第一次就异常，先查版本、模板、温度、mask或缓存，而不是先把clip范围放宽。

本书有限动作实验正采用这个节奏：80轮rollout、每轮2次更新，共160次optimizer step；最后一轮actor_version为158。它没有异步队列，不能推论生产系统可无损容忍任意陈旧数据。

## 采样设置也属于分布

温度、top-p、top-k、重复惩罚会改变行为分布。生成时按截断分布采样、训练时却把原始softmax当行为概率，重要性比值可能不再对应所假设的分布。生产实现需要明确处理这一差异；本代码从完整categorical分布直接采样，不做截断或温度变换。

长回答因长度上限中断时，不能悄悄把它当作自然EOS。截断状态会影响奖励、mask与回报；保留结束原因，才有办法诊断“模型学会早点结束”还是“系统把尾部丢了”。

> **一句话听懂**：轨迹包含行为版本、概率与结束原因，回答文本只是其中一部分。

> **到这里，你应该已经能听懂：**“调用工具是动作，工具返回是观察，最终奖励在轨迹结束才给。”
