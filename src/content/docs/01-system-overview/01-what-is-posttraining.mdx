## 现场问题

一个基座能接着写完算术教材，却在“只输出答案”时继续写题解；换成聊天模型后，它按要求回答，却也可能自信地算错。

> 会预测下一个 token，与按目标完成用户任务，差在哪里？

## 后训练承接什么，改变什么

**后训练（Post-training）**通常承接已有语言模型，使用示范、偏好、可验证结果或教师反馈，改变它在目标任务上的条件输出分布。它不仅是套聊天模板，也不保证所有变化都只是“激发现有能力”；训练可能学习新行为、新知识或新策略，能否获得需要测量。

| 路径 | 主要输入 | 监督从哪里来 | 如何判读 |
| --- | --- | --- | --- |
| 预训练 / 持续预训练 | 通常是大规模文本或领域语料 | 文本里的后续 token | 分布建模、覆盖、下游任务 |
| SFT | prompt 与示范回答 | 希望模仿的回答 token | 条件 NLL、指令和任务表现 |
| 偏好优化 | 同一 prompt 下的比较 | chosen / rejected 或其他反馈 | 配对偏好与实际生成 |
| 在线 RL | 模型采样的轨迹 | 结果、规则、人工或模型评分 | 奖励、独立任务质量和副作用 |

这不是互斥分类法：项目可能交替收集数据和训练，阶段名称也不统一。关键是写出**当前样本、目标、采样分布与评测条件**，不是仅凭“第二阶段”三个字判断算法。InstructGPT 给出一条具体的人类反馈路径，DeepSeek-R1 给出另一种多阶段实例；都不意味着所有项目必须依次 SFT→DPO→RL。[1][2]

## 怎样把需求变成可验收目标

“更聪明”无法直接验收。把需求改成：“对冻结的加法问题集，按纯十进制字符串回答，使用同一模板、贪心解码、最多 4 个新 token；分别记录答案正确和格式正确”。随后再加入真实产品需要的多语、拒答、长对话等任务，不能从一道加法推广。

贯穿本书的中文场景是“2+3，只输出数字”。代码将它映射成原创 ASCII 模板 `Q:2+3\nA:`，答案为 `5`。这个映射是教学约定，不是模型理解中文指令的证据。

## 本书的实验承诺

正文区分三类数字：手算假设、引用他人结果、绑定代码/环境的本机实测。SFT/DPO 使用 68,608 参数的小因果语言模型，随机初始化；有限动作 RL 实验只有 48 个参数。**两者都是机制夹具，不能叫作在成熟基座上复现了大模型后训练效果。** 默认无需网络数据、API、CUDA 或生产框架。第6章会同时给出变好与变差的实际指标，不把训练 loss 下降当作能力证明。

> **一句话听懂**：先说明要改变哪种行为、用什么反馈和证据，再选择后训练方法。
