## 现场问题

团队说“只训练1%的参数，所以显存也只用1%”。短跑却依然因为长回答激活而OOM。

> 可训练参数减少，哪些内存会减少，哪些仍然存在？

<SectionQA id="3.2" mode="ask" />

## 参数更新的两种接口

全参数微调直接更新选定基座的全部可训练权重。**LoRA**冻结某些原矩阵，学习低秩增量：按矩阵作用方向，写成 $W'=W+sBA$，其中 `W[d_out,d_in]、B[d_out,r]、A[r,d_in]`，s是缩放约定。应记录注入哪些投影、r、alpha/scale、dropout与基座身份。[1]

若原矩阵64×64、r=4，LoRA的A/B共 `4×64+64×4=512` 参数，原矩阵为4096；这是该矩阵的8倍差异，不是整个模型显存的8倍，更不是1%。

| 存储 / 计算 | 只更新adapter后怎样变化 |
| --- | --- |
| adapter参数与优化器状态 | 需保存和更新 |
| 冻结基座权重 | 仍需前向使用，通常仍占存储 |
| 激活与反传路径 | 仍需支持adapter梯度，长度/实现会影响 |
| 最终输出logits | 不会因为adapter少就消失 |
| 部署产物 | adapter需配基座；合并还取决于结构/精度/实现 |

不能把“冻结参数没有参数梯度”误读成“冻结层不需要反传任何激活”。适配器之前的可训练部分仍可能需要经过这些算子的梯度链。

## 本书语言模型究竟是什么

TinyPolicy使用257字节词表、width64、1个Pre-LayerNorm因果Transformer block、4头注意力、FFN宽256、可学习位置表32、输入输出权重共享、dropout0；独立参数实际68,608。block为归一化→注意力→残差，再归一化→FFN→残差，最后总归一化与输出头。

本项目运行的是**全参数FP32微调机制**，没有实现LoRA、量化或分片。本节LoRA矩阵是手算，不是本机性能报告。后训练不要求更换原模型的位置编码或注意力架构；生产项目要承接基座的实际结构与tokenizer。

## 交付前怎么核对adapter

先核对基座权重哈希与模块名，再检查adapter参数形状。若同名模型换了revision，能够load并不保证语义相同。冻结参数清单、trainable计数及一次更新前后差分能帮助发现“计划只训adapter，实际把embedding也解冻”的问题。

> **一句话听懂**：LoRA减少指定更新矩阵的自由度与状态，不等于同比减少整个训练系统开销。
