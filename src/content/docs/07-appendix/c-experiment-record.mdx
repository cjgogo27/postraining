## 每次实验先填这些字段

| 字段 | 要写什么 |
| --- | --- |
| 问题与对照 | 只改变什么，什么保持相同 |
| 来源 | 基座/教师/参考、数据组、模板与评分版本 |
| 目标 | mask、sum/mean、β、KL方向、有效分母 |
| 采样 | actor版本、温度/截断、组数、结束原因 |
| 计划 | batch、长度、更新数、优化器、预算 |
| 评测 | dev/test角色、固定题、解码、抽取、配对 |
| 环境 | 软件、设备、精度、线程与代码身份 |
| 产物 | checkpoint、raw outputs、metrics、失败日志 |
| 结论边界 | 实测、手算、未运行设计分别列明 |

## 本书的一次真实判读

DPO相对SFT的固定pair排序14/23→17/23，而终点greedy严格生成1/23→0/23；这是同一23题、同模板/预算下两种指标，不是两个算法的普遍优劣证明。没有多种子、独立产品测试或大模型，因此不做显著性和能力泛化声明。

## 下一轮可以怎样设计

若要研究训练长度，预先规定候选终点，用dev选择，再在未参与选择的test验收。若研究偏好数据，固定基座和训练预算，比较负例来源并保留原始生成；若研究奖励，先固定输出检查评分器，再固定评分器更新策略。此处是设计建议，未写入本项目成绩。
