## 为什么“查到正确状态”还不是一个训练目标

同样一次成功，可能来自可靠查询，也可能来自碰巧猜中。我们要优化的是策略在一类任务上的**期望表现**，不是让某一条日志的奖励变大。先定义任务怎样发生、模型能做什么、何时结束，再选PPO或其他方法。本页接在[token与梯度基础](/postraining/00-reading-guides/05-essential-foundations/)之后，属于第4章的概念入口。

以下订单数值均为独立构造的算例，不是模型能力或用户满意度实测。符号沿用[Spinning Up的RL定义与价值关系](https://spinningup.openai.com/en/latest/spinningup/rl_intro.html)，再映射到语言模型自己的接口。

## 1. 先把任务写成决策过程

| RL对象 | 工单里的含义 | 必须明确的接口 |
| --- | --- | --- |
| 初始任务分布 | 哪些用户、订单状态、异常类型会出现 | train/dev/test任务组及抽样权重 |
| 环境状态s | 订单表、权限、已调用工具、剩余预算 | 哪些信息真实存在，是否会自行变化 |
| 观察o、历史h | 用户问题、模型动作和工具返回 | actor实际能看到什么，不能提前看到答案 |
| 策略π(a\|h) | 在当前历史下选查询、参数或答复的分布 | token/宏动作定义、模板和采样设置 |
| 转移P | 动作怎样改变环境并产生下一观察 | 工具执行、异常、超时和状态副作用 |
| 奖励r | 本步结果或结束时任务评分 | 规则、版本、单位，失败状态是否有分数 |
| 终止 | 成功、任务失败或真正耗尽任务预算 | 与仅停止本段采样、padding分开 |

**MDP**要求状态足以描述后续条件分布；**POMDP**考虑只能看到部分状态。把历史喂给Transformer可以提供更多信息，却不会自动补出未查询的数据库内容。网络参数在训练时更新，环境状态在交互时改变，是两条不同的变化链。

一次完整回答可视为一个宏动作，也可展开成逐token决策。前者便于看整回答奖励，后者便于计算条件logp和逐位置价值；二者的折扣时间、长度权重和估计器必须对齐，不能一边按整任务计奖励、一边默认每个token都得了这份奖励。

## 2. reward、return、V、Q、A各回答什么

假设查单成本−0.1，随后正确答复得1。取γ=1时，两步奖励是 `[-0.1,1]`，从查单前开始的回报G为0.9；从答复前开始的G为1。如果γ=0.9，查单前的折扣回报为0.8。折扣改变了目标中远期结果的权重，不是一个与任务无关的数值小技巧。

$$G_t=\sum_{k=0}^{T-t-1}\gamma^k r_{t+k},\qquad V^\pi(s)=\mathbb E_\pi[G_t\mid s_t=s],\qquad A^\pi(s,a)=Q^\pi(s,a)-V^\pi(s).$$

本书记r_t为动作a_t之后的即时奖励；有的教材将它记作R_(t+1)，应先对齐时间再比较公式。有限时限任务还要把剩余时间/预算纳入状态或价值索引。

| 量 | 直觉 | 在训练中的用途 |
| --- | --- | --- |
| r | 这一步给了多少反馈 | 奖励器/环境输出 |
| G | 从这里往后累计得到多少 | 蒙特卡洛目标与评测回报 |
| Vπ | 在这里按π行动，平均能得多少 | 状态基线、价值估计 |
| Qπ | 这里先选特定动作，再按π行动能得多少 | 动作评价或价值学习 |
| Aπ | 这个动作比该状态下的平均水平好多少 | 策略梯度的权重 |

critic学V或Q；奖励模型预测评分，二者不是同一职责。同样终端得1分，若任务成本不同，回报不同；同样回报0.9，若所在状态的预期不同，优势也不同。

## 3. Bellman、蒙特卡洛和TD怎样接到GAE

构造一个状态：以概率0.5直接答复，期望回报0.4；以概率0.5花0.1查单，查到后按固定策略答对概率0.9。则Q(直接)=0.4，Q(查单)=−0.1+0.9=0.8，V=0.6；两个动作优势分别−0.2、+0.2，策略加权后平均为0。

这里“当前结果 + 下一状态的预期价值”就是Bellman一致性的直觉；它不是额外创造奖励。**蒙特卡洛**等整段结束再用实际G；**TD**用实际当步奖励加预测的下一V自举。TD通常不必等很久，但下一V估错也会进入学习信号。GAE再按γλ累计TD残差，连接短期自举与更长的实际结果；[4.2](/postraining/04-online-rl-distillation/02-ppo-advantage-and-kl/)有两步递推。

<summary>Q-learning、actor-critic和model-based是不是另一套后训练术语</summary>

Q-learning路线学习动作价值，再借助它选动作；actor-critic显式训练策略，并用价值估计辅助更新。它们的模块可以重叠，不宜画成互斥名称树。model-based RL还使用环境转移/奖励模型作规划；**语言模型本身很大**，不代表已获得正确的环境模型。训练框架、奖励模型、critic都不应因此改名“世界模型”。[Spinning Up算法分类](https://spinningup.openai.com/en/latest/spinningup/rl_intro2.html)

LLM有巨大离散动作空间、长轨迹和容易查询的log概率，故本书重点是策略梯度。离线Q学习的分布外动作风险见[RL地图](/postraining/00-reading-guides/06-rl-map/)，不将通用连续控制算法配置直接搬到LLM。

## 4. 价值估计为什么能影响策略，而不是代替策略

策略梯度用固定采样信号加权动作logp的梯度；价值估计帮助形成“比预期好多少”的信号。一个状态下不依赖当前动作的基线，其精确期望梯度贡献为0，但具体估计器的噪声、偏差和归一化仍要检查。V预测越准不等于任何设置都取得最低梯度方差。

从这里到算法的逻辑是：采样估计期望 → 降低估计波动 → 有限复用旧样本 → 控制代理更新。分别进入REINFORCE、基线/GAE、PPO的ratio/clip。GRPO改用同题一组样本比较；OPD改由教师提供更密集的分布监督。不要先把它们排成“后者完全替代前者”的代际表。[RLHF Book的策略梯度章](https://rlhfbook.com/c/06-policy-gradients)

## 5. 探索、熵和KL怎样影响这条链

若某种查询从未出现，奖励器无法告诉优化器它成功过。采样温度、候选数与任务课程影响能见到什么；但温度和top-p也会改变行为概率，不能只保留原始softmax作为μ。

熵描述策略分布的分散程度，熵项可鼓励保持选择空间；KL描述相对某个指定参考分布的变化。它们不是同一个量，也不保证更多随机选择就更好。长回答熵、调用数和任务成功率要联合看；“发现更多行为”和“更偏向已知成功行为”可能需要不同数据/预算。[统一后训练综述§2–3](https://arxiv.org/html/2604.07941v2#S3)

## 6. 把概念交给训练系统

读到这里，可以沿同一对象查五个接口：任务定义决定采样器拿哪些问题；采样器交动作与行为logp；评分器交reward及状态；估计器交停止梯度的return/advantage/价值目标；learner交成功更新后的权重版本。系统必须同时保存这些身份。

[1.3总图](/postraining/01-system-overview/03-posttraining-system-architecture/)把SFT、偏好、RL与蒸馏接入共同生命周期；[5.4](/postraining/05-evaluation-diagnosis/04-training-rollout-orchestration/)再把相同学习目标放到GPU池、通信、队列和检查点上。算法目标是“学什么”，系统安排是“怎样保持这个目标的语义并完成计算”。两者要一起验收。
