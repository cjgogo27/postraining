## 同一个工单助手，为什么能有这么多名字

我们希望助手根据订单表回答“订单A17发货了吗？”。起初直接把订单状态放进问题；后来让它自己决定是否调用查询工具；再后来分成查单员和答复员。这时“在线RL、PPO、agentic、多智能体、OPD”可能同时出现，却分别回答不同问题。

先用这张表定位，再读公式。本文及本轮新增的数字例子都是独立教学构造；真正执行的数值检查在[6.3](/postraining/06-tools-practice/03-finite-action-rlvr/)。

| 要回答的问题 | 分类轴 | 在工单任务里看什么 |
| --- | --- | --- |
| 训练中能否继续采集经历？ | online / offline | 能否让新策略再查单、获得新结果 |
| 经历由哪一个分布生成？ | on-policy / off-policy | 行为分布μ与当前π是否相同，历史轨迹是否复用 |
| 什么东西告诉策略好坏？ | 人类反馈、程序验证、教师分布 | 偏好、任务结果、下一token分布各提供不同信息 |
| 怎样估计并优化信号？ | REINFORCE、PPO、GRPO等 | 基线、优势、ratio、clip和归约 |
| 多少次决策构成任务？ | 单轮、agentic、多智能体 | 是否与环境反复交互，是否有多个决策者 |

RLHF/RLVR不是与PPO竞争的算法名称；agentic RL不指定必须用GRPO；多进程并行采样也不会自动变成多智能体RL。OPD/OPSD首先是蒸馏路径，可用与策略梯度有关的估计器，仍须说明教师信号和具体目标。

## 在线不等于联网，离线不等于off-policy

**online RL**指学习过程中可用更新后的策略继续收集数据，不要求接入互联网。6.3的本地表格策略每轮重新采样，因此在RL的数据采集意义上是online；整个程序同时可以断网运行。

**offline RL**指训练主要使用预先收集的固定数据，不能在优化中通过新环境交互补齐证据。**off-policy**则说明学习所针对的策略与行为策略不同。在线采集的旧数据也可被off-policy方法复用；不能把这两个英文词当同义词。[离线RL教程§2–3](https://arxiv.org/html/2005.01643v3#S2)

```text
可继续采集： π0 → 收集D0 → 更新π1 → 收集D1 → 更新π2
固定数据：   预先收集D  → 更新π1 → 仍用D  → 更新π2

两条路径都要另问：当前训练用到的数据，是由哪个μ生成的？
```

PPO通常按近似on-policy的节奏收集一批、有限次复用、再刷新；同一批第二次更新时π已变化，不能声称每个mini-batch始终来自当前π。PPO的剪裁代理并不使它成为可以无限复用任意历史数据的通用离线RL算法。

### 一份固定日志为什么不能证明没试过的动作好

设日志只包含动作A，已知其平均奖励0.6，从未试过B。两个可能世界都与日志一致：世界甲里B奖励0，世界乙里B奖励1。对各以0.5概率选A/B的目标策略，期望回报分别是0.3和0.8。更多次拟合同一份日志也无法分辨这两个世界。

这叫**覆盖不足**：行为策略没有支持目标策略想选的动作。重要性加权需要目标分布的支持被行为分布覆盖，μ(B)=0时不能计算一个有意义的π(B)/μ(B)。有限数据里“没观测到”与真实概率为0又有区别：即便概率非零，样本太少仍有高方差。

因此离线RL常需要行为约束、保守价值估计或不确定性处理。对多步任务，Q值自举还可能把未见动作的高估不断传回前面状态。SFT模仿已记录动作、DPO利用固定偏好比较，均有各自目标；“数据集固定”本身不足以说明已经解决多步离线RL。[教程§2.4、§4.2–4.5](https://arxiv.org/html/2005.01643v3#S4)

## 从REINFORCE到PPO，再到组相对方法

| 遇到的困难 | 引入的工具 | 还没有解决什么 |
| --- | --- | --- |
| 字符串/工具动作不可直接求导 | 用奖励加权log概率梯度 | 抽样噪声与探索覆盖 |
| 同一个1分在不同状态含义不同 | 减状态基线，估计优势 | critic误差、延迟归因 |
| 采样昂贵，想有限次复用 | 当前/旧策略ratio与PPO clip | 任意陈旧数据、全部状态分布变化 |
| critic开销或估计困难 | REINFORCE+基线、RLOO、GRPO | 同题多样本成本、恒定奖励组 |
| 长回答训练出现长度权重/数值问题 | 检查token归约、采样与序列ratio | 一套通用最优配置 |

按[4.2 PPO](/postraining/04-online-rl-distillation/02-ppo-advantage-and-kl/)手算两步GAE和正负剪裁，再读[4.3](/postraining/04-online-rl-distillation/03-grpo-and-rlvr/)的GRPO/RLOO/DAPO/GSPO。PPO的“近端”来自代理目标设计，不是每一步概率必然受硬约束的承诺。

## Agentic、多智能体、蒸馏分别加了哪一层

```text
单次回答：      问题 → 回答 → 评分
工具型agent：  历史 → 动作 → 环境观察 → 下一动作 → 任务结果
协作系统：     查单员动作 → 共享消息/环境 → 答复员动作 → 团队结果
教师蒸馏：     学生前缀 → 教师评分同一前缀 → 分布/梯度监督
```

Agentic RL要说明隐藏环境状态、动作/观察边界、工具失败和延迟奖励；多智能体还要说明各角色可见信息、是否共享参数、对方策略版本与团队信用分配。[附录E](/postraining/07-appendix/e-agentic-multi-agent-rl/)把同一工单扩展为两角色，给出可枚举的梯度算例。

OPD让学生采样自身会走到的前缀，教师在这些位置提供监督；OPSD的一种具体形式让同一模型的教师分支额外看到训练解答。教师分支停止梯度，不代表“没有外部信息”。先读[4.5](/postraining/04-online-rl-distillation/05-distillation-and-opd/)，再查[10份重点资料](/postraining/07-appendix/f-rl-reading-list/)。

## 三条使用路线

- 学生：必要基础 → 本页 → 4.2两步GAE与clip → 4.3组优势 → 4.5分布监督 → 6.3数值检查。先会解释每个分母，再打开变体折叠区。
- 工程师：4.1行为身份 → 4.2冻结边界 → 5.4采样/训练差异 → 附录E轨迹契约 → 6.3检查报告。
- 产品/PR：先问“谁采数据、谁评分、实际优化什么”，再问“固定哪些任务、是否真正执行、总成本包含什么”。多agent运行成功一次不等于经过MARL训练。
